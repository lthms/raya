# CI/CD

`raya`’s repository is hosted [on GitHub](https://github.com/lthms/raya), and
leverages GitHub Actions for continuous integration and deployment.

## Workflows

### `docs.yml`

This is the workflow generated by `zensical new`. It ensures this documentation
is re-generated and published every time a new commit lands on the `main`
branch. It needs no repository secret: it authenticates to GitHub Pages through
OIDC, thanks to the `id-token: write` permission.

### `terraform.yml`

This workflow runs various Terraform built-in checks to ensure the correctness
of the committed files, then runs `terraform plan` to show the impact of the
change on production. It is triggered by pushes to `main` as well as by pull
requests, so a change is checked before it lands.

Nothing is ever applied automatically as of yet.

## Terraform Backend

Terraform state is hosted on [HCP Terraform](https://app.terraform.io), under
the `raya` workspace belonging to the `lthms` organization. Its execution mode
is set to `Local`.

## Secret Management

To let the GitHub runners connect to the various services involved in `raya`’s
deployment, several repository secrets were created:

| Secret | Role |
| ------------ | ---- |
| `TF_API_TOKEN` | Authentication to HCP Terraform |
| `HCLOUD_TOKEN` | Authentication to Hetzner Cloud |

These secrets are exposed to the `terraform` workflow
(`.github/workflows/terraform.yml`) as environment variables.

`TF_API_TOKEN` is fed to Terraform via the `TF_TOKEN_app_terraform_io`
environment variable (since we are using app.terraform.io)[^doc].

The other ones hold values intended for sensitive Terraform variables declared
in `variables.tf`. Such values are fed to Terraform using the `TF_VAR_` prefix
convention. For instance, `HCLOUD_TOKEN` initializes the `hcloud_token` variable
by setting `TF_VAR_hcloud_token`[^local].

```yaml
TF_VAR_hcloud_token: ${{ secrets.HCLOUD_TOKEN }}
```

!!! warning

    Because the workspace uses `Local` execution, `terraform plan` runs on the
    GitHub runner and its output is written to a public Actions log. Any
    sensitive Terraform variable must therefore be declared as such (`sensitive
    = true`).

    Note that this only redacts variables: resource attributes (addresses,
    `user_data`, key fingerprints) may still appear in cleartext by default.
    Wrap any expression carrying a secret in `sensitive()` when its value does
    not already derive from a sensitive variable. For instance, `user_data =
    sensitive(templatefile(...))`.

[^doc]: See [Terraform documentation on the
    subject](https://developer.hashicorp.com/terraform/cli/config/config-file#environment-variable-credentials)
[^local]: `TF_VAR_`-prefixed environment variables are consumed by Terraform
    because the `raya` workspace uses the `Local` execution mode.
